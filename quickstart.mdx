# Quickstart

This guide explains how a developer can find the Rejesha Green technical documentation, understand the system structure, and contribute documentation updates.

## Prerequisites

Before starting, you should have:

- Access to the `achirooshamimu/docs` GitHub repository
- GitHub access to the `main` branch
- A modern web browser
- Basic familiarity with Markdown or MDX
- Permission to create or review documentation changes

## Explore the documentation

Start with the following pages:

1. [System Overview](/overview) — understand the platform purpose and capabilities.
2. [System Architecture](/architecture) — review the platform components and documentation delivery workflow.
3. [Frontend](/frontend) — understand the presentation layer.
4. [Backend](/backend) — understand the application and API layer.
5. [Security Architecture](/security) — review authentication, authorization, and security controls.
6. [Deployment](/deployment) — understand how changes move from GitHub to the live site.
7. [Developer Guide](/developer-guide) — follow the development and contribution guidance.

## Contribute a documentation change

1. Open the `achirooshamimu/docs` repository on GitHub.
2. Create or edit a Markdown or MDX file.
3. Keep the file in the correct documentation folder.
4. Update `docs.json` if adding a new page to navigation.
5. Commit the change to the `main` branch.
6. Wait for Mintlify to validate and deploy the update.
7. Open the live site and verify the page, navigation, links, and formatting.

## Verify the update

After deployment:

- Check **Mintlify → Insights → Activity**.
- Confirm the deployment status is **Successful**.
- Open the live documentation site.
- Confirm the updated page appears in navigation.
- Check that Mermaid diagrams render correctly.
- Test internal links and search.
- Confirm that no starter-kit placeholder text remains.

## Documentation conventions

Use the following structure when creating a new technical page:

- Purpose
- Intended audience
- Main concepts or workflow
- Dependencies and prerequisites
- Configuration or usage steps
- Error conditions
- Security considerations
- Deployment considerations
- Verification status
